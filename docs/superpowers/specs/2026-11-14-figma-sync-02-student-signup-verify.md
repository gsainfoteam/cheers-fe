### 2.2 약관 동의 (`334:6123` / `334:6011`, 완료 `334:6365` / `334:6235`): 일치 ✅

01장에서 보지 못한 **모바일 본 화면**과 **모두 체크한 상태**를 이번에 확인했다. 결과는 모두 일치한다.

- **문구:** `약관 동의` / `서비스 이용에 필요한 약관을 확인해 주세요.` / `전체 동의` / `[필수] 서비스 이용약관` / `[필수] 개인정보 수집·이용 동의` / `동의하고 다음`

- **완료 상태:** 체크박스 `bg-ink-fill`·`border-ink`·흰 체크, 버튼 Disabled → Primary. 코드는 필수 항목이 모두 체크되면 버튼을 켠다(`terms.tsx:74-77`). 지금은 두 항목이 모두 필수라 결과가 같다.

#### 2.3.2 도메인 오류를 입력 중에 표시 — P1 🔶

도메인 오류 상태에서 **버튼이 Disabled다.** 서버의 400으로 오류를 띄우려면 버튼을 먼저 눌러야 하므로, 이 상태는 **제출 전에 클라이언트에서 검사한다**는 뜻이다.

- 값을 `trim().toLowerCase()`한 뒤 `@gm.gist.ac.kr`로 끝나는지 본다. 아니면 버튼을 끄고 `gm 메일을 입력해주세요.`를 보여 준다.

- 서버 패턴 `^[^+]+@`은 `+` 주소를 400으로 막는다. 이 경우 위 문구는 맞지 않는다(gm 메일인데 "gm 메일을 입력"이라고 나옴).
- 🔶 **D2-4:**
  - 오류를 띄우는 시점: 칸을 떠날 때(blur)인지, 입력하는 동안인지. 디자이너에게 묻는다. 정해지기 전에는 이 저장소의 다른 칸처럼 **칸을 한 번 떠난 뒤**로 둔다.

  - `+` 주소에 쓸 문구. 디자이너에게 묻는다.
  - `입력해주세요`(붙여 씀)는 저장소의 `입력해 주세요`와 다르다. 오타인지 디자이너에게 묻는다.

### 2.4 인증번호 입력 / 만료 / 불일치 → `verify.tsx` `CodeStep`

틀, 제목 `인증번호 입력`, 설명 `학교 이메일로 보낸 6자리 번호를 입력해 주세요.`, 읽기 전용 이메일 칸, 라벨 `인증번호`, **도움말 자리의 타이머** `남은 시간 04:32`, 만료 문구, `이전` 폭은 모두 일치한다. 시안에는 칸 옆의 `재전송` 링크가 **없다.**

정책 메모 `375:14473` 원문: *"인증·프로필 정책: 인증번호 유효시간과 재발송 제한은 서버 정책 확인이 필요합니다. 닉네임 생성·중복·글자 수, 필수 학과와 관심 분야 선택 범위·최대 입력 길이도 확정해야 합니다."* 숫자는 시안이 정하지 않는다. 지금처럼 `expires_at`·`resend_available_at`으로 계산하는 방식을 유지한다.

#### 2.4.1 문구 — P1 🔶

- 주 버튼 `인증 확인`(`:243`)을 **`인증하기`** 로 바꾼다. 대기 중 문구 `확인 중…`은 시안에 없지만 유지한다(보내기 버튼의 `보내는 중…`과 같은 규칙).
- 불일치 문구 끝에 `(n회 남음)`이 붙어 있다(`:316`). 시안에는 없다. → 🔶 **D2-5: 남은 횟수를 보여 줄지 디자이너에게 묻는다.** 답이 오기 전에는 유지한다. 시도 횟수 제한을 모르고 틀리다가 막히는 쪽이 더 나쁘기 때문이다.
- 쿨다운 버튼 `다시 받기 (mm:ss)`도 시안에 없는 보강이다. 유지하고 디자이너에게 알린다.

#### 2.4.2 410 만료·404 처리 — **P0**

명세(`/verify/code`)의 응답은 **400 틀림(`remaining_attempts`) / 404 진행 중인 요청 없음 / 410 만료**다. 코드는 다음과 같다.

- 410을 처리하지 않는다. 일반 문구 `인증에 실패했습니다. 다시 시도해 주세요.`로 떨어진다(`:321`).
- 404를 `인증번호가 만료됐어요.`로 보여 준다(`:318-319`). `api/student.ts:76` 주석은 "5번 틀리면 404"라고 적었다.
- 404·410을 받아도 `expired`가 false로 남는다. 그래서 버튼이 `인증 확인` 그대로이고, 죽은 코드로 계속 제출할 수 있다.

바꿀 것:
1. `expired = 시계상 만료 || 서버가 404·410을 줌`으로 넓힌다. 둘 다 시안의 만료 화면(만료 문구 + `인증번호 다시 받기`)으로 보낸다. 기기 시계가 틀려도 서버 응답이 기준이 된다.

### 2.8 정보 수정(`/me/edit`)에 번지는 영향

`me_/edit.tsx`는 가입과 **같은 칸 묶음**(`StudentInterestsField editing`, `StudentActivitiesField`, `StudentPortfolioField`, `StudentContactFields editing`)을 쓴다(`:157-166`). 이 장의 변경이 그대로 따라간다.

- 기타 관심 분야: 지금은 저장된 사용자 값이 **값에는 있지만 화면에 보이지 않는다.** 2.5.3을 하면 바로잡힌다.
- 첨부: 기존 파일·링크를 지우지 않도록 `attachmentsOf`의 "기존 첨부 다시 보내기" 규칙을 유지한다. 업로드 URL 발급은 가입을 마친 상태라 지금도 허용된다.
- 알림 설정: 기본값을 가입과 다르게 **저장된 값**으로 채운다(`studentEditDefaults`).
- 정보 수정 화면의 문구·배치는 `05 · 학생 마이페이지` 섹션 장에서 시안과 맞춘다. 이 장에서는 **깨지지 않게만** 한다(`tsc`, 화면 확인).
