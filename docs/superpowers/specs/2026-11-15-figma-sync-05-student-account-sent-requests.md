### 5.7 작업 체크리스트 (권장 순서)

> **구현 기록 (2026-11-15).** 아래 체크한 항목은 `42-sync-figma-design-service-policy` 작업 트리에 반영했다(커밋 전). 구현하면서 정한 세부 사항:
> - `studentContactOf(me)`는 줄이 아니라 `{ email, phone }`을 돌려준다(전화번호는 `formatPhone`을 거친 값). 마이페이지가 순서를 직접 적는다. 첨부 줄은 이제 어느 화면도 쓰지 않아 `studentProfileRowsOf`의 `withAttachments` 옵션과 `attachmentLabelsOf`를 지웠다.
> - 보낸 신청 내용이 `compact`로 바뀌면서 `ProfileRow`의 `comfortable` 크기는 쓰는 곳이 없어 지웠다. 남은 크기는 `compact`(96) · `card`(112, 6장) · `document`(96).
> - 정보 수정의 저장된 파일은 href가 `blob:`이 아니면 저장된 파일로 보고 `AttachmentLink`(presigned 갱신)로 그린다. 렌더 중에 ref를 읽지 않으려는 것이다(eslint `react-hooks/refs`).

> - 화면은 로그인이 필요해 이 환경에서 눈으로 확인하지 못했다. 아래 "검증"의 화면 항목은 스테이징에서 본다.

③은 목록과 상세가 같은 DTO를 쓴다. 목록 응답을 가볍게 두고 싶다면 목록에는 `department`·`hashtags`만, 상세에는 네 개 모두면 된다. 로고 presigned URL을 목록 50건마다 만들 필요는 없다(행에 로고가 없다).

**임시값을 넣는 방법.** 화면마다 `?? null`을 흩어 두지 않고 한 파일에 모은다. BE 필드가 오면 이 파일에서 그 줄만 지운다.

```ts
// src/lib/pending-be-fields.ts — 방향
// TODO(#46): BE가 필드를 내려 주면 해당 줄을 지운다
export function withPendingGraduatedFields(g: RequestGraduated) {
  return { department: null, hashtags: [], company_logo_url: null, links: [], ...g };
}
export function withPendingCardFields(c: CheersCard) {
  return { department: null, ...c };
}
export function withPendingReceivedFields(r: ReceivedRequest) {
  return { interests: [], activities: [], ...r };
}
```

- 기본값을 **앞에** 두고 응답을 뒤에 펼친다. `api:sync`로 `dto.ts`에 필드가 생기면 실제 값이 기본값을 덮으므로, 이 파일을 지우기 전에도 화면이 바로 실제 값을 쓴다.
- 임시값은 모두 "없음"(`null`, `[]`)이다. **가짜 글자(예: `DA사업부`)는 넣지 않는다.** 화면은 이미 "없으면 줄을 그리지 않는다" 규칙으로 만들어져 있어서 BE가 와도 화면 코드를 고칠 필요가 없다.
- ⑥은 필드가 아니라 동작이라 이 파일에 넣지 않는다. 판정 함수 하나(`isAccepted(status)` = `status === "contact_shared"`)로 모아 두고, BE가 상태 이름을 바꾸면 그 함수만 고친다.
