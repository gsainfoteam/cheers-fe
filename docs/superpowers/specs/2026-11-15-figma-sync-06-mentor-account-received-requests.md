## 6. 선배 계정·받은 신청

읽은 날: 2026-11-15. 기준은 `c7814f0`(04장 반영) + **커밋하지 않은 05장 작업 트리**다. 비교한 코드:

- 컴포넌트: `components/ui/{profile-row,profile-identity,request-item,empty-state,confirm-dialog,attachment-group}.tsx`, `components/{employee-badge,brand-cat,access-message}.tsx`
- 도우미: `features/profile/{mentor-fields,contact-channel-fields}.tsx`, `lib/{mentor-contact,pending-be-fields,profile-form}.ts`
- API: 2026-11-15 `bun run api:sync`로 다시 받음 → **바뀐 곳 없음**(`dto.ts` 일치, 응답 DTO 31개 + 페이징 3개). #46에 답이 아직 없다.

**섹션 하나에 화면이 다섯이고, 가장 큰 변화는 받은 신청 내용이다.**
1. **받은 신청 내용이 모달에서 한 장짜리 화면이 됐다.** `← 받은 신청 목록` + 화면 제목 + 학생 프로필 카드. 옛 `연락 방법` 카드 둘(학생에게 직접 연락 / 내 연락처 공유)은 없어졌다.
2. **흐름이 두 단계가 됐다(D5-1 정책의 화면).** ① `커피챗 수락하기` → 확인 → ② `커피챗 시작하기`: `학생 연락처`(내가 먼저 연락하기 → 문자/메일) · `내 연락처`(내 연락처 공유하기 → 확인 → `공유 완료`). 옛 `연락처 공유 완료` 한 장은 없어졌다.
3. **수락 API가 생겼다(2026-11-15, #46 1번).** `커피챗 수락하기` → `POST /cheers/received/{id}/accept` → 상세를 다시 받으면 학생 연락처가 채워진다. `내 연락처 공유하기`는 그대로 `share-contact`이고 수락한 신청에서만 된다(D6-1, 6.5.3). 처음에는 수락을 브라우저에만 기록하는 임시 구현이었고 [#47](https://github.com/gsainfoteam/cheers-fe/issues/47)에서 바꿨다.
4. **선배 마이페이지가 5장 학생과 같은 카드 한 장 뼈대가 됐다.** 연락처 카드·`사원증 미리보기`·고양이 도장·`ProfileIdentity`가 없어졌다.
5. 받은 신청 목록·정보 수정은 거의 맞다. 빈 목록이 한 줄로 줄었고, 탈퇴한 학생 행이 새로 생겼다.

- 수락 판정: `isAccepted(status)`(= `contact_shared`) **또는** 로컬 기록. 이미 공유한 신청은 수락한 것으로 본다.
- 수락 전에는 학생 이메일·전화번호를 **화면에 그리지 않는다**(카드째 없다). 응답에서 가리는 것은 BE 몫이다(#46 1번 1).
- **한계:** 수락이 서버에 남지 않는다. 다른 기기·브라우저에서는 수락 전으로 보이고, 학생은 수락 여부를 모른다(공유해야 선배 연락처가 보인다). 수락 상자에 처리 중·실패 상태가 없다.
- 백엔드가 바뀐 뒤 할 일은 [#47](https://github.com/gsainfoteam/cheers-fe/issues/47)에 체크리스트로 적었다.

</details>

**BE에 다시 요청할 것**은 6.9 ⑥에 정리했다. 핵심: 수락 API(예: `POST /cheers/received/{id}/accept`), 수락과 공유를 따로 나타내는 상태(`accepted_at`과 `contact_shared_at`), 학생 쪽 `SentRequestDto`에도 같은 구분.

#### 6.5.6 내가 먼저 연락하기 — P1

시안(`1245:17001`): `커피챗을 시작하세요` / `학생의 연락처로 먼저 연락하여 커피챗을 시작하세요.` / Secondary 폭 전체 두 개 `문자로 연락하기`, `메일로 연락하기`(사이 8). **닫기 버튼이 없다.**

✅ **D6-7 (구현):** 주석의 "가능하면 작성 창으로, 아니면 복사"를 폭으로 나눴다.
| | 모바일(`< lg`) | 데스크톱 |
|---|---|---|
| 문자 | `<a href="sms:{숫자}">문자로 연락하기</a>` | **`전화번호 복사하기`** → `navigator.clipboard` → 글자가 `전화번호를 복사했어요`로 바뀌고 1.2초 뒤 닫힘(주석 "버튼 누르면 창 알아서 닫히게") |
| 메일 | `<a href="mailto:…">메일로 연락하기</a>` | 같음 |
- 데스크톱 브라우저 대부분은 `sms:`를 열 앱이 없다. 그래서 데스크톱만 복사로 바꿨다.
- 학생이 켜지 않은 채널의 버튼은 그리지 않는다. 링크를 누르면 상자를 닫는다.
- 복사 결과는 `aria-live`로도 알린다. 복사 권한이 없으면 아무 일도 하지 않는다(번호는 카드에 보인다).
- 닫기 ✕가 없어 base-ui `Dialog`(바깥 누르기 · Esc로 닫힘)로 만들었다. 확인 상자(`AlertDialog`)와 달리 되돌릴 수 없는 일을 묻지 않기 때문이다. ✕를 넣을지 디자이너에게 묻는다(D6-8).

#### 6.5.7 오류 화면 — P1

받은 신청 내용이 한 장이 되면서 오류(다른 계정 404·403, 접근 불가 410·400, 서버 장애)도 **07장 시안처럼 한 장**으로 그린다. `AccessMessage`를 `bare` 없이(데스크톱 560 카드) `PageContainer` 안에 둔다. 목록 위 모달에 넣던 옛 차이(§7 #17)는 닫힌다. 학생 쪽 `SentErrorDialog`는 그대로다.

### 6.8 작업 체크리스트 (권장 순서)

> **구현 기록 (2026-11-15).** 아래 체크한 항목은 `42-sync-figma-design-service-policy` 작업 트리에 반영했다(커밋 전, 05장 작업과 같은 트리). 구현하면서 정한 세부 사항:

**⑥ 수락 흐름 — 보강 (P0)**

5장에서는 "수락이 `share-contact`와 같은 동작인가, 새 API인가"를 물었다. **6장 시안으로 답이 정해졌다: 다른 단계다.** 선배는 수락한 뒤 학생에게 먼저 연락할 수도(`내가 먼저 연락하기`), 자기 연락처를 공유할 수도(`내 연락처 공유하기`) 있다.

| 항목 | 요청 |
|---|---|
| 수락 API | `POST /api/v1/cheers/received/{id}/accept`(이름은 BE가 정함). 성공하면 그 뒤 상세에서 `RequestStudentDto.email/phone`이 내려온다 |
| 수락 전 학생 연락처 | `RequestStudentDto.email/phone`을 `null`로(#46 1번 1, 그대로) |
| 상태 | 수락과 공유를 **따로** 알 수 있어야 한다. 예: `status: requested \| viewed \| accepted \| contact_shared` 또는 `accepted_at`·`contact_shared_at` 두 시각. 받은 신청 상세(`ReceivedRequestDetailDto`)와 목록 모두 |
| 공유 API | `share-contact`는 수락한 신청에서만 허용(수락 전이면 409 등). 연락 수단이 없는 선배의 409는 그대로 |
| 연락 수단이 없는 선배의 수락 | 수락은 되는가(학생 연락처만 보면 되므로 가능해 보인다) |
| 학생 쪽 | `SentRequestDto`·`SentRequestDetailDto`에도 수락과 공유를 구분하는 값. 5장 `선배 연락처`(D6-10)와 상태 아이콘(D5-10)이 쓴다 |
